⚙️ Установка и запуск
Клонируйте репозиторий:

bash
git clone https://github.com/your-username/proacne-qa-automation.git
cd proacne-qa-automation
Создайте виртуальное окружение и установите зависимости:

bash
python -m venv venv
source venv/bin/activate  # Для Windows: venv\Scripts\activate
pip install -r requirements.txt
Установите браузеры для Playwright:

bash
playwright install chromium
Запустите тесты:

bash
pytest -v tests/Proachprogram.py --headed
(Флаг --headed используется для визуальной отладки. В CI/CD пайплайне тесты запускаются в headless режиме)

🐞 Результаты тестирования и найденные дефекты
В ходе тестирования формы проверки состава был выявлен критический дефект, зафиксированный в Jira (Issue: TEST1-46).

Суть дефекта:
При вводе валидного списка ингредиентов и нажатии на кнопку «Проверить» форма не отправляется. Обработчик события на стороне клиента блокирует отправку запроса.

Детали воспроизведения (Steps to Reproduce):

Перейти на страницу https://proacne-program.com/check.

Ввести валидный список ингредиентов в текстовое поле.

Нажать на кнопку «Проверить».

Ожидаемый результат (Expected Result):
Форма отправляется на сервер (в DevTools Network фиксируется POST-запрос). На странице отрисовывается блок с результатами анализа состава, комедогенные ингредиенты подсвечиваются красным цветом.

Фактический результат (Actual Result):
Клик по кнопке игнорируется JS-скриптами сайта. Страница остается в исходном состоянии. В DevTools (вкладка Network) отсутствуют исходящие сетевые запросы при клике. Результат анализа не появляется.

Приоритет / Серьезность: High / Major (Блокирует основной функционал страницы).
Отчет с приложенными скриншотами (DevTools, Network) прикреплен к задаче в Jira.

⚠️ Особенности тестирования платформы Tilda
Сайт разработан на CMS Tilda. При написании автотестов были учтены следующие архитектурные особенности платформы:

Валидация и обработчики событий: Стандартный метод .fill() может не активировать внутренние валидаторы Tilda. В тестах используется press_sequentially() для полной имитации пользовательского ввода (эмуляция событий keydown, keyup, input).

Дублирование DOM-структуры: Tilda часто генерирует скрытые дубликаты элементов для разных разрешений экрана (адаптивность). Для поиска нужного элемента используются строгие локаторы (.first, get_by_text), а для проверок — ассерты на наличие текста (to_contain_text), а не на CSS-видимость (to_be_visible), чтобы избежать ложных срабатываний на скрытых дублях.

AJAX-запросы: Формы Tilda отправляют данные асинхронно. Для синхронизации теста с моментом отрисовки результата используется ожидание wait_for_load_state('networkidle') и дополнительные таймауты.
